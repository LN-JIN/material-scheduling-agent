# 01 需求与验收边界

## 业务目标与范围

输入一份素材及其时间要求，Agent 读取素材、调用合成规则审核、查询本地可用时段，并保存排期草稿。模型根据工具观察决定下一步；审核结论、时间授权和保存结果由程序验证并导出。

每个请求只处理一个 `material_id`。当前交互入口是命令行，素材、规则、既有排期均为本地合成数据，草稿保存于 SQLite。项目不连接真实内容平台，不执行发布，也没有让用户点击确认或执行确认回调的界面。`completed` 表示本轮草稿任务完成，不代表内容已发布；`pending_confirmation` 表示草稿仍待人工确认。

真实模型固定为 `qwen3.8-max`。离线模式使用明确标记的确定性模拟器，只能验证工具流程、持久化与边界，不能证明真实模型作出了相同决策。

## 输入约定

输入为一个 JSON 对象；字段校验见 [domain.py](../src/domain.py)。

| 字段 | 要求 | 含义 |
|---|---|---|
| `request_id` | 必填，非空字符串，最长 200 字符 | 原始请求的全局幂等标识 |
| `material_id` | 必填，非空字符串，最长 200 字符 | 本轮唯一素材 |
| `requested_time` | 必填，带时区的 ISO 8601 字符串 | 用户原来要求的开始时间 |
| `time_requirement` | 必填，`fixed` 或 `window` | 固定时刻，或明确授权的时间窗口 |
| `allowed_start`、`allowed_end` | `window` 时必填，均带时区且开始早于结束 | 授权窗口，必须容纳素材的整个时长 |
| `note` | 可选字符串 | 补充数据，不用于覆盖结构化时间授权或规则 |

发布占位长度由 rules.json.scheduling_policy.posting_interval_minutes 定义，当前合成业务规则为同一渠道每次发布保留 60 分钟的排期窗口；它不是视频播放时长。素材的 playback_duration_seconds 仅为内容元数据。为兼容旧输入，缺少该策略时仍将旧 duration_minutes（默认60）解释为发布占位分钟，并在工具结果标记 legacy_duration_minutes_or_default。示例数据使用 `main` 渠道。`note`、标题和正文中的指令式文字都视为数据，不能授权替换素材、绕过审核或写入“已经确认”。

## 时间授权与确认

| 原始要求与审核情况 | 草稿可以选择的时间 | `confirmation_status` |
|---|---|---|
| `fixed`，原时间可用，且无软风险 | 原时间 | `not_required` |
| `fixed`，原时间被占用，且无硬阻断 | 原时间起未来 7 天内的候选时间，仅作为改期提案 | `pending` |
| `window`，且无软风险 | 整个素材区间均落在 `[allowed_start, allowed_end]` 内的候选时间 | `not_required` |
| 任一时间要求，但命中软风险 | 满足时间边界的候选时间 | `pending` |
| 缺必要素材信息或命中硬阻断 | 不得保存排期草稿 | 未进入确认判定 |

`not_required` 表示当前草稿不需要新增确认；系统没有生成 `confirmed` 状态的通道。固定时间发生变化时，模型不能把“找到了空位”解释成“用户同意改期”。窗口授权也不能解除内容软风险所要求的确认。

保存待确认草稿只记录提案，不使排期生效，也不执行发布。因此固定改期或软风险不要求先收集确认再调用 `save_draft`：应先保存带有 `pending` 状态的本地草稿，观察保存结果后结束。后续将提案变成已确认有效排期需要额外明确同意，而本项目没有该确认执行界面。

候选槽位优先考虑原时间，最多返回 5 个；候选是备选方案，不要求彼此互斥。不同请求已保存的草稿与本地既有排期都占用其渠道上的时间，待确认草稿同样占用。

## 合成审核规则

规则实现见 [tools.py](../src/tools.py)，当前规则文件见 [rules.json](../data/rules.json)。这些规则用于展示可验证的工程边界，不代表真实平台政策、法律结论或完整内容安全审核。

| 检查 | 当前合成判定 | 业务结果 |
|---|---|---|
| `title` 或 `text` 缺失、空白 | `missing_information`，返回 `missing_fields` | 需要补信息，不能排期保存 |
| `rights_status` 为 `owned` 或 `licensed` | 版权标签检查通过 | 继续其他审核；不表示系统实际核验版权 |
| `rights_status` 缺失、`null`、空白、`unknown` 或其他未识别值 | `missing_information`，`missing_fields` 含 `rights_status` | 需要补齐明确标签，不能排期保存 |
| `rights_status == denied` | 硬阻断 | 不能由模型绕过 |
| 标题或正文包含“未经授权转载” | 硬阻断 | 返回命中依据，不保存 |
| 标题或正文包含“绝对领先” | 软风险 | 可以保存待确认草稿，保留风险证据 |
| `required_terms` | 当前为空 | 若配置，缺少要求词会按规则阻断 |

关键词采用不区分大小写的子串匹配，不进行语义判定。`rights_status` 是素材数据中的合成标签，系统未接入真实权利核验。扩展规则支持必填字段、要求词、禁用词、风险词、最大长度和枚举取值；规则文件缺失、无效类型、未知规则或严重级别在初始化时拒绝，不静默视为通过。显式空对象 {} 表示只启用内置素材字段检查，和规则文件丢失有不同含义。

## 六项必验场景

下表定义验收目标，实际执行证据以测试输出及生成的 Trace 为准；这里不预填通过数量或真实模型运行结果。

| 验收点 | 输入或故障条件 | 应验证的行为 |
|---|---|---|
| 1. 正常链路 | 素材完整、规则通过、原时段空闲 | 模型完成读取、审核、查询、保存后的观察与结束；输出真实 `draft_id`，库中只有一份草稿 |
| 2. 信息缺失 | 已找到素材，但标题、正文为空，或版权标签不明确 | 审核返回缺失字段，最终 `needs_input`，无草稿；不能虚构素材内容或版权标签补齐 |
| 3. 规则风险 | 分别命中硬阻断和软风险 | 硬阻断最终 `blocked` 且无草稿；软风险保留命中证据并保存为 `pending_confirmation` |
| 4. 时段冲突 | 原时段被占用，或查询后占用发生变化 | 固定时刻改期保持待确认；明确窗口内可按授权排期；保存时发现新冲突必须重查，不能保存过期候选 |
| 5. 重复提交 | 原请求不变重复执行，含重启后重试 | 恢复同一 `draft_id`，不重复占位；同一个全局 `request_id` 改时间、素材或其他原始字段必须拒绝 |
| 6. 保存失败 | 提交前失败、持续失败、提交后响应丢失 | 提交前回滚；持续故障最终 `failed`；响应丢失保持 `unknown` 并以相同原请求重试核对，不伪报失败或创建第二份草稿 |

自动化入口为 [tests/test_acceptance.py](../tests/test_acceptance.py)。真实模型证据需另看 `examples/` 中实际生成的输入、输出与 Trace，不能以离线流程测试替代。

## 输出与状态边界

业务输出必须包含审核、风险、原时间、建议时间、确认状态、保存状态、草稿标识与任务状态。CLI 将业务 JSON 和逐行 JSON Trace 分开写入指定路径。

| 输出字段 | 可信来源 |
|---|---|
| `review`、`risks` | 工具实际计算的规则检查及命中证据 |
| `review_status`、`missing_fields` | 从审核状态和缺失字段同步的顶层字段 |
| `risk_reasons` | 硬规则失败与软风险警告的规则标识、说明、命中证据组成的字符串列表；缺信息另列 |
| `original_time` | 已绑定原始请求中的 `requested_time` |
| `suggested_time` | 最新查询的候选，或已保存草稿 |
| `confirmation_status` | 原始时间授权、是否改期、审核软风险共同决定 |
| `pending_items` | 可信推导的待确认清单：固定改期的 `time_change`，以及软风险的 `rule_risk` |
| `save_status`、`draft_id` | 实际工具执行状态及 SQLite 已保存记录 |
| `task_status`、`run_completed`、`stop_reason` | 本轮执行状态和停止原因 |
| `draft_status` | 已保存草稿的业务状态，与本轮执行是否完整分开 |
| `next_step` | 基于上述可信状态生成的后续处理提示 |

`pending_items` 的 `time_change` 项包含 `original_time`、`suggested_time`；`rule_risk` 项包含 `rule_id`、`message`、`evidence`。固定改期与软风险并存时分别列出；窗口内调整不产生改期待确认项，但软风险仍保留。硬阻断或缺信息时不生成待确认草稿事项。上述字段不接受模型填入的自报结果。

几个容易混淆的边界如下：

| 情况 | 当前实现的结果 |
|---|---|
| 请求不合法，或复用 `request_id` 改变原始载荷 | `rejected`，不保存 |
| 首次读取时找不到 `material_id` | 工具返回 `material_not_found`、`retryable=false`；未形成审核或草稿。模型结束后为 `incomplete`，不是“审核通过”或 `needs_input` |
| 素材存在，但必填内容为空或版权标签不明确 | `review.status=missing_information`；模型结束后为 `needs_input` |
| 授权窗口过窄，或查询范围内无空位 | `no_available_slot`，不保存；固定要求下只表示未来 7 天提案范围内无候选 |
| 模型提前结束，尚无完整业务结果 | `incomplete` |
| 模型调用失败 | `incomplete`，保留已发生的真实保存状态 |
| 保存提交后响应丢失，模型尚未重试核对 | `save_status=unknown`；若模型此时结束，`task_status=unknown` |
| 达到 `max_steps` | 一律 `task_status=incomplete`、`run_completed=false`、`stop_reason=max_steps_reached` |

达到上限与是否落库是两个维度。例如第 4 次模型动作刚完成保存，但没有额度让模型观察结果并执行 `finish`，本轮仍为 `incomplete`；同时必须保留 `save_status=saved`、真实 `draft_id` 和独立 `draft_status`。不得把已提交事实改写成保存失败。相同原请求可用于后续核对恢复。

## 明确不覆盖的能力

不提供批量素材调度、真实平台发布、确认执行界面、草稿确认状态升级、草稿取消或自动过期释放、完整内容安全审核、真实版权核验、分布式数据库部署。既有草稿重试返回原草稿快照，不会因随后更改规则或排期文件而自动重排。

## 可选软偏好

note 可表达合法候选之间的软偏好，不能扩大硬授权。可选 candidate_context.json 提供每个候选的合成互动指数（0–100）和客服在线标记。工具只附加事实、不按偏好排序，模型显式选时；无数据不能编造指标。该实验不代表真实流量预测。
